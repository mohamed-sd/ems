# أداة فحص إدارة المبيعات — دليل الاستخدام

دليلٌ مختصر: كيف تشغّل الفحص، وكيف تقرأ نتيجته.

---

## ما هذه الأداة؟

بعد أي تعديل تعمله في النظام، تشغّل أمرًا واحدًا فيفتح **كل شاشات إدارة المبيعات
(46 شاشة)** بمستخدم حقيقي، ويجرّب فيها **العرض والإضافة والتعديل والحذف**، ثم يقول لك:

> **هل تغيّر شيء عن آخر مرة كانت الأمور فيها سليمة؟ وإن تغيّر — أي شاشة بالضبط، وأي عملية، ولماذا.**

وينظّف بعده كل ما أدخله، فلا يترك أثرًا في بياناتك.

---

## قبل التشغيل

تأكد أن **WAMP أخضر** (Apache و MySQL يعملان). الأداة تفتح الشاشات فعليًّا عبر
المتصفح الداخلي، فلو كان الخادم متوقفًا لن تعمل — وستخبرك بذلك بوضوح.

---

## الأوامر — ثلاثة فقط

افتح موجّه الأوامر في مجلد المشروع `C:\wamp64\www\ems` ثم:

### ① الفحص الكامل (هذا الذي ستستعمله دائمًا)

```bash
C:\wamp64\bin\php\php8.2.30\php.exe tests/dept_suite/run.php
```

يأخذ حوالي **3–5 دقائق**. يفحص كل شيء ويقارن بخط الأساس.

> **اختصار بلا كتابة أوامر**: في المجلد نفسه ملف **`run_sales_test.bat`** —
> انقر عليه مرّتين ويشتغل الفحص الكامل ويعرض النتيجة ثم ينتظر حتى تقرأها.

### ② فحص سريع (دقيقة واحدة · لا يكتب شيئًا في القاعدة)

```bash
C:\wamp64\bin\php\php8.2.30\php.exe tests/dept_suite/run.php --quick
```

يفتح الشاشات ويتأكد أنها تُعرض بلا أخطاء — **لا يجرّب الإضافة والتعديل والحذف**.
استعمله للتأكد السريع بعد تعديل بسيط.

### ③ تثبيت خط الأساس

```bash
C:\wamp64\bin\php\php8.2.30\php.exe tests/dept_suite/run.php --save-baseline
```

يحفظ الحالة الحالية باعتبارها «الوضع الصحيح» الذي يُقارن به لاحقًا.
**متى تستعمله؟** اقرأ قسم «خط الأساس» في آخر الدليل.

## كيف تقرأ النتيجة

التقرير ثلاثة أقسام:

### القسم ① — جدول مختصر

```
  العملية      ناجح   فاشل   غيرُ موجود   محجوب   متعذّر
  عرض           43      0          0        3       0
  إضافة         19      0         27        0       0
  تعديل         17      0         29        0       0
  حذف           14      0         32        0       0
  حارس          19      0         27        0       0
```

معاني الأعمدة الخمسة — **مهم جدًّا**:

| الرمز | المعنى | هل هو مشكلة؟ |
|---|---|---|
| ✅ **ناجح** | العملية تمّت وتأكّدنا من القاعدة | لا |
| 🔴 **فاشل** | العملية لم تتم، أو تمّت ولم تُحفظ | **نعم — هذا ما تبحث عنه** |
| ⚪ **غير موجود** | الشاشة أصلًا ما فيها هذه العملية (تقرير مثلًا ما فيه «إضافة») | **لا — هذا طبيعي** |
| 🔒 **محجوب** | الشاشة ردّت المستخدم لأن صلاحيته لا تسمح | لا — لكن راقبه إن تغيّر |
| ⏭ **متعذّر** | لم نستطع تجربتها (مثلًا: الإضافة فشلت فلا يوجد سجل لنعدّله) | تابعٌ لفشلٍ قبله |

> ⚠️ **لا تخلط بين 🔴 فاشل و⚪ غير موجود.** رقم 115 في عمود «غير موجود» ليس خطأً —
> معناه أن 115 عملية غير موجودة أصلًا في شاشاتها (مثل: الحذف في شاشة تقرير).

### القسم ② — الفاشل الآن بالاسم

كل عملية فاشلة تظهر باسم الشاشة ومسارها والسبب الحرفي الذي قالته الشاشة:

```
  🔴 سجل العملاء
     Clients/clients.php  ·  إضافة
     السبب: لم يُكتب صفٌّ في `clients` — قالت الشاشة: «لا توجد صلاحية إضافة عملاء جدد ❌»
```

### القسم ③ — الفرق عن خط الأساس ← **هذا أهم قسم**

هنا الجواب على سؤالك «تعديلي أثّر على شنو؟»:

```
  🔴 انكسر منذ آخرِ أساس (3) — هذا ما أحدثه تعديلُك:

     ▸ سجل العملاء  ·  إضافة
       Clients/clients.php
       كان: ✅ PASS   ⇒   صار: 🔴 FAIL
       لم يُكتب صفٌّ في `clients` — قالت الشاشة: «لا توجد صلاحية إضافة عملاء جدد ❌»
```

وإن لم يتغيّر شيء:

```
  ✅ لا شيءَ تغيّر. الإدارةُ كما تركتَها (230 عمليةً مطابقة).
```

قد تظهر أيضًا:

- 🟢 **تحسّن** — كان فاشلًا وصار ناجحًا (أصلحتَ شيئًا)
- 🔵 **تبدّل** — تغيّرت حالته بلا حكم أفضل أو أسوأ
- ⚪ **أسطح جديدة** — شاشة أضفتَها ولم تكن في الأساس
- ⚫ **أسطح اختفت** — شاشة حذفتَها

## طريقة العمل اليومية

```
1. تعمل تعديلاتك في النظام (أي تعديل، كبير أو صغير)
        ↓
2. تشغّل:  run.php
        ↓
3. تقرأ القسم ③ فقط
        ↓
   ✅ «لا شيء تغيّر»  →  تمام، كمّل شغلك
   🔴 «انكسر (ن)»     →  اقرأ الأسماء، أصلح، وأعد التشغيل
```

---

## خط الأساس — متى تحدّثه؟

خط الأساس هو **صورة الحالة السليمة** التي تُقارن بها.

**حدّثه في حالتين فقط:**

1. بعد إصلاح ما انكسر ورجوع كل شيء أخضر.
2. بعد إضافة شاشات جديدة أو تغيير مقصود في سلوك شاشة.

**لا تحدّثه** وأنت ترى 🔴 لم تفهمه بعد — لأنك بذلك **تثبّت العطب باعتباره الوضع الطبيعي**،
فلا تراه الأداة مرة أخرى أبدًا.

الملف: `tests/dept_suite/baseline/sales.json`

## إذا حصل خطأ

| الرسالة | المعنى والحل |
|---|---|
| `⛔ تعذّر الاتصالُ بالقاعدة` | MySQL متوقف — شغّل WAMP |
| `⛔ فشل الدخول` | Apache متوقف، أو كلمة مرور المستخدم تغيّرت |
| `⛔ تعذّر بذرُ «...»` | القاعدة رفضت بيانات التهيئة — الرسالة تقول السبب |
| `بقايا في القاعدة: ن ⚠` | تشغيلة سابقة انهارت — نظّفها بالأمر أدناه |

**تنظيف البقايا:**

```bash
C:\wamp64\bin\php\php8.2.30\php.exe tests/dept_suite/run.php --sweep-only
```

## هل الأداة تغيّر بياناتي؟

**لا.** كل ما تنشئه يحمل البادئة `EMSQA` ويُحذف في نهاية كل تشغيلة، وتؤكّد لك ذلك في آخر التقرير:

```
  بقايا في القاعدة بعد الكنس: صفر ✅
```

وحتى لو انهار التشغيل في منتصفه، التشغيلة التالية تنظّف بقاياه تلقائيًّا قبل أن تبدأ.

> **ملاحظة**: الأداة تعمل على قاعدة البيانات الحقيقية (لا توجد قاعدة اختبار منفصلة).
> لذلك يُفضَّل تشغيلها على نسخة التطوير عندك، لا على خادم فيه بيانات عملاء حيّة.

## الملفات

| الملف | ما هو |
|---|---|
| `run.php` | الأمر الذي تشغّله |
| `engine.php` | المحرّك — **لا يعرف المبيعات، صالح لأي إدارة** |
| `manifest_sales.php` | وصف شاشات المبيعات الـ46 وحقولها |
| `baseline/sales.json` | خط الأساس |
| `results/sales_<تاريخ>.json` | نتيجة كل تشغيلة (سجل تاريخي) |

## تعميمها على إدارة أخرى

المحرّك عامّ ولا يعرف المبيعات إطلاقًا. لتغطية إدارة أخرى:

1. انسخ `manifest_sales.php` إلى `manifest_<اسم_الإدارة>.php`
2. غيّر قائمة الشاشات وحقولها والمستخدم الذي يفتحها
3. شغّل:

```bash
C:\wamp64\bin\php\php8.2.30\php.exe tests/dept_suite/run.php --dept=<اسم_الإدارة>
```

**لا يُعدَّل أي سطر في `engine.php`.**
