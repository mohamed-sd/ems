## 1. الملخّص التنفيذي المعماري
EMS منصّةُ إدارة معدّات/مقاولات (PHP إجرائي + MySQL) تُهاجَر تدريجيًّا — بلا كسر إنتاجي — من مونوليث متمركز حول الصفحة إلى معماريةٍ محوكمةٍ بأربع طبقات، عبر **«الخنق التدريجي» (Strangler)**: كل شاشةٍ تُنقل خلف **بوابة عزل الشركة `TenantDb`** واحدةً واحدة، بمقياسٍ صارم (`T3 = صفر نداء SQL خام`) وجولةٍ ذهبيةٍ مطابقةٍ بايتيًّا قبل/بعد.

| الترحيلات المطبَّقة (schema_migrations) | **47** |

## 2. النمط المعماري العام — أربع طبقات
1. **الأساس**: مونوليث إجرائي متمركز حول الصفحة (`*.php` بجذر كل وحدة) — الأغلبية العظمى.
2. **الحديثة الجزئية**: OOP + PSR-4 داخل `app/` (خدمات Excel، إلخ).
3. **الوحدات المكتفية ذاتيًّا**: أقسامٌ حديثةٌ نظيفة النمط (Procurement, Transport, Finance) — تُهاجَر كوحدة.
4. **نواة الحوكمة والعزل `app/Core/`**: `TenantDb` (بوابة العزل) · `EventPublisher`/`EventDispatcher` (الناقل) · `StateMachine` · `ServerId` · `TenantRegistry`/`TenantContext`. **هذه الطبقة تنمو مع كل إدارةٍ تُهاجَر.**

القاعدة الحاكمة: **الجديد يُضاف بجانب القائم لا محلّه**، وكل تحويلٍ قابلٌ للعكس (git revert / ترحيل down).

## 13. بوابة العزل `TenantDb` (ADR-02) — العقد والقنوات الخمس
**المبدأ**: لا شاشةٌ تلمس القاعدة مباشرةً؛ كلٌّ يعبر البوابة التي **تحقن عزل الشركة تلقائيًّا** وتفرض الحذف الناعم حصريًّا.

**سجل الجداول `TenantRegistry`** يصنّف كل جداول القاعدة (~148) إلى: `T_TENANT` (مستأجَر بcompany_id) · `T_CHILD` (معزول بأبيه) · `T_GLOBAL` (كتالوج/منصّة) · `T_MONITOR_PASS` (عبور مراقبةٍ مُسجَّل).

**القنوات الخمس المحوكمة** (كلٌّ وُلد من حاجة هجرةٍ فعلية بقرار موثَّق):
1. **CRUD الأساس**: `insert/update/softDelete/select/selectOne/count` — حقن company_id، حذف ناعم، وحارس **الحصانة §12** (`immutable_key`: صفٌّ يحمل `idempotency_key` = حدثٌ منشورٌ على الناقل → يُرفض تعديله/حذفه حتى للسوبر).
2. **`runInTransaction` (§9)**: الأزواج الكتابية الذرّية (قيد+حدث، رأس+سطور، التوأمان) — أيّ رفضٍ داخليّ = rollback الكل.
3. **`scopedQuery` (§10)**: المجاميع/الـJOINs — رمز `{TENANT_SCOPE}` تحقنه البوابة؛ الإثراء LEFT JOIN حصرًا؛ ممنوع ذكر company_id في SQL.
4. **`forAllTenants`** (سوبر، رؤية عابرة محروسة).
5. **`forSystem`** (cron بلا جلسة — دورة شركاتٍ معزولة، تُحقن في helpers عبر `*_gate_override`).

**التغطية الراهنة**: البوابة مُنفَّذة على المرحلة 1 (20 ملفًا) + **الإدارة المالية كاملةً (23 ملفًا، T3=0 مقيس)**.

## 14. الناقل الحي للأحداث (ADR-10) — العقد والتدفق + عقد قابلية التوزيع 🆕
**الطبقات**: `EventPublisher` (نقطة كتابةٍ واحدة، عطالة أثرٍ بـ`idempotency_key` فريد) → `fin_financial_events` (الدفتر) → `EventDispatcher` (توزيع exactly-once بالمؤشّر `cursor_event_id` + `ems_event_deliveries` + `ems_event_dead_letter`) → المستهلكون. المُصالِح في `cron_events.php` يعيد نشر الفائت ويرصد اليتيمة كل دورة.

**ضمان «مرّة واحدة بالضبط» قائمٌ ومختبَر** (الأرصفة 66/66: ناشر 34 · موزّع 15 · آلة حالة 17).

### 14.7 🆕 عقد قابلية التوزيع والحدث العكسي (A-1 · 2026-07-12)
تجهيز مخطّطٍ (لا منطق) على `fin_financial_events` + جدولٌ جديد — بترحيل K2 واحد، **صفر لمسٍ لكود الناشر/الموزّع**:
- **`event_uuid` CHAR(36) `DEFAULT (UUID())`**: معرّفٌ كونيٌّ لكل حدث. الـdefault القاعديّ يملؤه **كل إدراج** (ناشر/بوابة/خام) تلقائيًّا ⇒ لا حاجة لتعديل أيّ كود. (تقنيًّا: يُضاف nullable ثم `SET DEFAULT` منفصلًا — UUID() ممنوعٌ داخل `ADD COLUMN` لأن DDL يُسجَّل STATEMENT — ثم backfill per-row تحت ROW binlog.)
- **`event_status` ENUM('active','reversed') + `reverses_event_id`**: عقد الحدث العكسي (C6) — محورُ دورة حياةٍ منفصلٌ عن `state` سير المالية. **المنطق (النقض المعوِّض) مؤجَّلٌ** بالقيد الرابع (لا يُبنى قبل أول مستهلك جديد)؛ المخطط يرسي البنية بالمعيار الفاصل.
- **`ems_processed_events`** (جدولٌ جديد): عطالة استهلاكٍ موزّعة — عقدٌ يُفعَّل عند تعدّد الموزّعات (الضمان الحالي بالمؤشّر+deliveries؛ هذا للتوسّع الأفقي).

**التحفّظ الملزم** (قرار 2026-07-09) ما زال ساريًا: مكوّنات الناقل الحيّة (`EventPublisher`, `EventDispatcher`, `timesheet_event_hook`, `cron_events`) **لا تُلمس كشاشة**؛ هجرة المالية احترمته (صفر تعديل عليها، مقيس git diff).

**البنود المؤجّلة للناقل**: منطق الحدث العكسي · نماذج القراءة `dash_*` · تسجيل مستهلكٍ جديد. (§33)

## 16. حارس صلاحية الفعل (ADR-06/K10) + CSRF المتدرّج
- **حارس الفعل**: `EMS_ACTION_GUARD=enforce` (نافذ). يغطّي سطح AJAX (403 JSON منظَّم لغير المخوَّل)؛ الصفحات العادية تحمل فحوصها.
- **CSRF المتدرّج (ADR-05)**: حقنٌ مركزيٌّ تلقائيٌّ (ob-handler + csrf.js) + إنفاذٌ لكل مسار عبر `CSRF_ENFORCE_PATHS` في `.env`.
  - **الحالة الراهنة (بعد A-3)**: مُنفَّذ على `/Finance/,/Procurement/,/Transport/,/Opportunities/` — **الوحدات المهاجَرة كاملةً**، بإشارة سجلٍّ نظيفة (صفر مخالفة متصفح) وتحقّقٍ حي (بلا توكن→403، بتوكن صحيح→يمرّ). التراجع = حذف المسار من `.env` (بلا نشر كود).
  - القاعدة: كل وحدةٍ تُهاجَر تدخل القائمة يوم إغلاقها؛ عند تعميم الكل يُقلب `EMS_CSRF_ENFORCE=true`.

## 34. سجل التغيير عن v3 (2026-07-10 → 2026-07-12)
1. **الإدارة المالية: من 17/23 إلى 23/23 خلف البوابة** — أُغلقت عائلة F3 (الأحداث الحية): `import_events` · `journal_form` · `unit_records` · `events_list` (الجذر) · `fin_helpers`+`cron_finance` (مقترنان)، إضافةً إلى `executive_dashboard`. لكلٍّ: T3=0 + golden مطابق بايتيًّا + إثبات أثرٍ حي + commit مستقل. **الوحدة كلها صفر SQL خام (مقيس).**
2. **عزل الحدثين التجريبيين 54/55** (رواتب 2.65M + وقود 0.95M) بقرار مالكٍ صريح بعد تحقيقٍ جنائيّ (بذرٌ تجريبيّ، مصادرُ غير موجودة) — عزلٌ ناعمٌ ذرّيٌّ مع قيدَيهما، down مُختبَر.
3. **عقد قابلية التوزيع + الحدث العكسي (A-1)**: `event_uuid` (default قاعدي) + `event_status`/`reverses_event_id` + `ems_processed_events` — ترحيل K2، صفر لمس كود الناقل.
4. **لوحة مراقبة الناقل (A-2)**: `admin/bus_monitor.php` + مقياس التأخّر.
5. **توسيع CSRF (A-3)**: من `/Finance/` إلى الوحدات المهاجَرة الأربع.
6. **أرقام القاعدة**: الجداول 147→**148** (+`ems_processed_events`) · الترحيلات 45→**47** · أعمدة الدفتر 38→**41**.
7. **الخط الأحمر صامد**: صفر تعديلٍ على مكوّنات الناقل الحيّة عبر كل ما سبق (مقيس git diff).

> **ثبات المرجعية**: v1/v2/v3 محفوظة تاريخًا. عند أيّ إغلاق وحدةٍ جديدة (الصيانة تالية) يُحدَّث هذا الملف أو يُصدَر v5.
