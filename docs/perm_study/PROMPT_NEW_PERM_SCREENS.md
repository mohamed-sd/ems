# ⓐ الجوابُ أوّلًا: نعم يمكن — وقد نُفِّذ نظيرُه

**السابقة:** `2028_04_27_perm_screens_registration.php` سجّلت **تسعَ شاشاتٍ** للدور 15.
**والدرسُ الذي خرجت به:** «البندُ الظاهرُ يحتاج **عشرةَ سجلّاتٍ لا أربعة**» — ثمَّ اكتُشف **حادي عشرَ وثاني عشرَ** بعدها.

**و«إدارة الحسابات» في نظامك = الدور 15 «إدارة الصلاحيات»** (حسابُه اسمُه `حسابات` · #56) — وهو **مالكُ هذا الباب سلفًا**، ومساحتُه `DEP-08`.

# البرومت — انسخه كما هو

---

## المهمّة

أنشئ **ثلاثَ شاشاتٍ** لإدارةِ قوالبِ الصلاحيّاتِ وإسنادِ المستخدمين، وسجّلها تحت **بابٍ ومجموعةٍ جديدَين** باسم **«نظام الصلاحيات الجديد»**، مملوكةً للدور **15 «إدارة الصلاحيات»** في المساحة **`DEP-08`**.

## ⛔ اقرأ هذا قبل أن تكتب سطرًا

**سابقةٌ منفَّذةٌ في هذا المستودعِ تحمل الوصفةَ ومصائدَها. اقرأها كاملةً أوّلًا:**

```
database/migrations/2028_04_27_perm_screens_registration.php
database/migrations/2028_04_28_resync_gov_profile_items.php
Governance/auth_profiles.php      ← الشاشةُ التي تعرض القوالبَ ولا تكتبها
Governance/auth_grants.php        ← الشاشةُ التي تسحب المنحَ (النمطُ المعتمَد للكتابة)
includes/permissions_helper.php:337-420   ← نقطةُ القرارِ المركزيّة
```

**ولا تبدأ ببناءٍ قبل أن تُخرِج قياسًا** لعددِ السجلّاتِ التي تحتاجها شاشةٌ ظاهرةٌ فعلًا اليوم — بأخذِ شاشةٍ تعمل (`Governance/perm_matrix.php`) وعدِّ كلِّ صفٍّ يذكر مسارَها في كلِّ جدول.

## ② التسجيل — **اثنا عشرَ سجلًّا لكلِّ شاشة**

عشرةٌ من السابقةِ + واحدٌ اكتُشف بعدها + واحدٌ جديدٌ لهذا الباب:

| # | السجل | ملاحظةٌ حاسمة |
|---|---|---|
| 1 | `modules` | `code` = المسارُ حرفًا: `Governance/perm_profile_editor.php` |
| 2 | `role_permissions` | `role_id=15` · الأقفالُ الأربعة |
| 3 | **`gov_profile_items`** | ⛔ **الأهمّ** — `item_kind='screen'` · `item_ref` = **كودُ الشاشة** |
| 4 | `nav_items` | `label_ar`/`route` **لا** `label`/`link` · `door` = البابُ الجديد |
| 5 | `nav_canonical` | `status='APPROVED'` · `application_state='DEPLOYED'` |
| 6 | `nav_targets` | `target_id` بنمطِ `NT-DEP-08-nnn` |
| 7 | `nav_placements` | `workspace_id='DEP-08'` · `group_id` = المجموعةُ الجديدة |
| 8 | **`nav_workspace_placements`** | ⛔ **السجلُّ الحاكمُ للتصيير** · `status='ACTIVE'` |

| 12 | `gov_space_appearances` | ظهورُ الشاشةِ في المساحة |

### ⛔ أربعُ مصائدَ مقيسةٍ من السابقة — **لا تُخمَّن**

| المصيدة | الصواب |
|---|---|
| **صيغةُ المسارِ تختلف بالجدول** | `nav_workspace_placements` يخزّنه **صغيرًا وبلا `.php`**: `governance/perm_profile_editor` — وكلُّ الجداولِ الأخرى بالحرفِ الكامل |
| **`role_permissions` وحدَها لا تكفي** | الحارسُ يقرأ **القالب**: شاشةٌ خارجَ `gov_profile_items` **تُمنَع رغمَ `can_view=1`** |
| **الأيقونةُ بأسلوبِ البيت** | `fa fa-…` (2,700 صفًّا) **لا** `fas fa-…` (4 صفوف) |
| **`nav_placements.group_id` ترقيمُ دليلٍ** | DEP-08 يستعمل 49..54 — **والمجموعةُ الجديدةُ رقمٌ جديدٌ يُحجَز، ولا يُقحَم في عنقودٍ قائم** |

## ③ البابُ والمجموعةُ الجديدان

**البابُ الحاليُّ للحوكمة `GOV`.** والمطلوبُ بابٌ يُميَّز:

```
door        = 'PERMNEW'
اسمُ المجموعة = «نظام الصلاحيات الجديد»
group_code   = 'PERM_NEW'
owner_role_id = 15
icon         = 'fa fa-user-shield'
```

⛔ **ولا يُنقَل بندٌ قائمٌ إلى البابِ الجديد.** الشاشاتُ الثلاثُ **وحدَها** فيه — وهذا شرطُ التمييزِ الذي طُلب: **ما تحت البابِ الجديدِ جديدٌ يقينًا.**

## ④ ما تفعله الشاشاتُ فعلًا — والمحظورات

### مسموح

| الشاشة | تكتب في |
|---|---|
| محرِّر القالب | `gov_profile_items` — إضافةٌ · حذفٌ · تعديلُ الأقفالِ الأربعة |
| إسناد المستخدم | `gov_authority_grants` — إسنادٌ · وسحبٌ (النمطُ القائمُ في `auth_grants.php`) |
| معاينة الأثر | **لا تكتب شيئًا** |

### ⛔ محظور

1. **لا تُعدَّل `role_permissions` من هذه الشاشات** — الجدولُ الأضعفُ حكمًا، وتعديلُه يوهم المستخدمَ بأثرٍ لا يقع.
2. **لا يُحفَظ تعديلٌ بلا سببٍ مكتوب** — بنمطِ `auth_grants.php` حيثُ السحبُ بلا سببٍ يُردّ.
3. **لا يُحفَظ تعديلٌ بلا عرضِ الأثرِ أوّلًا** — والمستخدمُ يؤكّد بعد رؤيتِه.
4. **لا تُتجاوَز بوّابةُ التجميد** `gov_policy_freeze`: مفتاحا `grants` و`profile_activation` **مفعَّلانِ الآن** — فالشاشةُ **تقرأ الحالةَ وتُعلِنها وتردُّ الحفظَ** ما دام التجميدُ قائمًا.
5. **لا تُخترَع مفردةٌ خارجَ ENUM** — تُشتقُّ من المخطَّط، فالقيمةُ الغريبةُ تصير `''` صامتًا.
6. **لا `item_ref` برقمِ الوحدة** — كودُ الشاشةِ حرفًا. **وكودٌ خاطئٌ لا يُخطئ بصوت**: يُكتَب البندُ ولا يُطابق شيئًا فتبقى الشاشةُ ممنوعةً وأنت تظنُّها مفتوحة.

## ⑤ الحوكمةُ الفنيّة

| البند | المطلوب |
|---|---|
| **الهجرة** | `database/migrations/YYYY_MM_DD_permnew_screens.php` **ومعها `_down.php` مجرَّبٌ فعليًّا** |
| **قيدُ الدفتر** | استدعاءُ `ems_migration_recorded()` — وهجرةٌ بلا قيدٍ تردُّ البوّابة |
| **CSRF** | كلُّ نموذجِ POST بحقلِ `csrf_token` صريح — **الحقنُ الآليُّ يغطّي `fetch`/`XHR` لا النموذجَ العاديّ** |
| **بوّابةُ المستأجر** | كلُّ استعلامٍ عبر `TenantDb`/`scopedQuery` — لا SQL خامٍّ في السطح |
| **العُدّةُ الموحّدة** | `ems-forms.css` · `EmsAlert` · `INJAZ DataGrid` — كما تفعل شاشاتُ `Governance/` القائمة |
| **الأثر** | كلُّ تعديلٍ يُقيَّد في `permission_audit_events` (عمودُ الزمنِ اسمُه **`at`** لا `created_at`) |

## ⑥ الإثباتُ المطلوبُ في ردِّك — **بالقياسِ لا بالسرد**

| # | الإثبات |
|---|---|
| ① | **قياسُ ما قبلَ البناء**: عددُ السجلّاتِ التي تحتاجها شاشةٌ ظاهرةٌ — باستعلامِه |
| ② | الاثنا عشرَ سجلًّا **لكلِّ شاشةٍ** مكتوبةً بعددِها الفعليّ |
| ③ | **دخولٌ حقيقيٌّ بحساب `حسابات` (#56)** وفتحُ الشاشاتِ الثلاثِ — HTTP 200 |
| ④ | **ظهورُ البابِ الجديدِ في سايدبارِه** — وصفرُ بندٍ قديمٍ انتقل إليه |
| ⑤ | **اختبارٌ سالب**: دورٌ آخرُ يفتح الشاشةَ ⇒ يُردّ |
| ⑥ | **اختبارُ الأثر**: أضف شاشةً إلى قالبٍ ⇒ أثبت أنَّ `get_module_permissions()` غيّرت حكمَها |
| ⑦ | **تجربةُ العكس**: شغِّل `_down.php` وأثبت رجوعَ الحالِ ثمَّ أعِد الهجرة |
| ⑧ | `tests/dept_suite/run.php` **قبل وبعد** — وصفرُ انحدارٍ في المبيعات |
| ⑨ | **وما تعذّر قياسُه: سمِّه ولا تخمّنه** |
