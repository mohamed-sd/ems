# العقد التقني لبوابة العزل / DAO — Tenant Gate Contract

**المرجع:** ADR-02 (EQUIP-ARC-R02 §2) · **هذا هو المخرَج ⑥** من حزمة المراجعة
**التنفيذ:** 2026-07-07 · **الكود:** `app/Core/` · **الاختبارات:** `tests/tenant_leak_test.php`
**الإلزام:** يقيّد بندَي معيار القبول المعماري §4: ① (كل استعلام عبر البوابة، لا mysqli خامًا) و② (اجتياز اختبار التسرّب قراءةً وكتابةً).

---

## 1. المبدأ والنطاق

- البوابة (`App\Core\TenantDb` عبر `ems_tenant_db()`) هي **الطريق الوحيد** لوصول الشاشات **المُهاجَرة** والوحدات **الجديدة** إلى قاعدة البيانات.
- الشاشات القديمة تبقى على mysqli الخام **حتى دور هجرتها** (R02 §3.4) — البوابة لا تغيّر سلوكها إطلاقًا (غير كاسرة بالبنية).
- المؤشر الحاكم (R02 §7): «نسبة الاستعلامات المارّة عبر البوابة = 100% **للشاشات المُهاجَرة**».

## 2. الضمانات (ما تتكفل به البوابة — لا يكتبه المطوّر أبدًا)

| الضمان | الآلية |
|---|---|
| عزل الشركة قراءةً | حقن `company_id = سياق الجلسة` آليًا في كل SELECT/COUNT |
| عزل الشركة كتابةً | فرض `company_id` على INSERT؛ تقييد UPDATE/softDelete بنطاق الشركة |
| منع تمرير الهوية | `TenantContext` يُبنى من الجلسة (`fromSession`) أو من الخادم (`forSystem`) حصريًا — لا مسار يقرأ هوية من `$_POST/$_GET`؛ تمرير `company_id` مغايرٍ في البيانات = **رفض + تسجيل «identity forgery»** |
| Fail-Closed | جدول غير مسجَّل / سياق بلا شركة / معرّف غير سليم / تلاعب بـ company_id في whereRaw ⇒ `TenantGateException` + حدث `tenant_gate_violation` في security.log |
| حقن SQL | prepared statements دائمًا؛ كل المعرّفات ضد `^[A-Za-z0-9_]+$` والسجل |
| أرشفة لا حذف (§4 ⑧) | لا يوجد DELETE في الواجهة أصلًا — `softDelete()` فقط، ويُرفض على جدولٍ بلا أعمدة حذفٍ ناعم؛ القراءة تستبعد المحذوف افتراضيًا (`includeDeleted` صريح) |
| التجاوز المرئي | القراءة العابرة للشركات عبر `forAllTenants($reason)` فقط: مدير أعلى حصرًا + تسجيل كل استدعاء (`tenant_gate_cross_tenant`) بموقع الاستدعاء والسبب |

## 3. سجل الجداول (`TenantRegistry`) — أربع فئات

| الفئة | العدد | السلوك |
|---|---|---|
| `T_TENANT` | 121 | حقن العزل قراءةً وكتابةً (+ علم `soft` للحذف الناعم) |
| `T_CHILD` | 3 | بلا company_id — يُعزل عبر أبيه (`EXISTS` على الأب)؛ إدراج ابنٍ يتحقق أن الأب مملوك للمستأجر |
| `T_GLOBAL` | 7 | مراجع نظام (roles، modules...): قراءة متاحة، كتابة للمدير الأعلى فقط |
| `T_RESTRICTED` | 10 | منصة/محرّكات لم تُهاجَر (admin_*، approval_*، schema_migrations...): **مرفوضة كليًا** حتى يُعرَّف عقدها مع هجرة وحدتها |

**قاعدة الجداول الجديدة:** أي جدولٍ يُنشأ بترحيلٍ يُسجَّل هنا في نفس الـ commit مصنَّفًا بوعي (مع `company_id` وأعمدة الحذف الناعم للمستأجَر — معيار §4). جدولٌ غير مسجَّل غير قابلٍ للاستخدام عبر البوابة أصلًا.

## 4. الواجهة (API)

```php
$gate = ems_tenant_db();   // هوية الجلسة الحالية — من config.php

$rows = $gate->select('mnt_breakdown', [
    'columns' => ['id', 'title', 'status'],
    'where'   => ['status' => 'open'],                 // تساوٍ مرتبط بمعاملات
    'whereRaw'=> 'created_at >= ?', 'params' => [$d],  // جزء حرٌّ يكتبه المطوّر (القيم عبر ? حصريًا)
    'orderBy' => 'id DESC', 'limit' => 50, 'offset' => 0,
]);
$row = $gate->selectOne('clients', ['where' => ['id' => $id]]);   // null إن لم يكن لمستأجرك
$n   = $gate->count('contracts', ['where' => ['status' => 1]]);
$id  = $gate->insert('mnt_breakdown', $data);          // company_id يُحقن — لا تمرّره
$aff = $gate->update('mnt_breakdown', $set, ['id' => $id]);
$aff = $gate->softDelete('clients', $id);              // ناعم حصريًا
$all = $gate->forAllTenants('لوحة إشراف المنصة');       // مدير أعلى + مسجَّل
```

**محظورات على المطوّر في الشاشات المُهاجَرة** (يكشفها grep في المراجعة):
- أي `mysqli_query/prepare` مباشر — البند ① من §4.
- ذكر `company_id` في أي `where/whereRaw/data` — العزل مسؤولية البوابة وحدها (المخالفة تُرفض runtime أيضًا).
- التقاط `TenantGateException` لإسكاته — الاستثناء يعني خللًا بنيويًا يُصلَّح لا يُبتلَع.

## 5. حزمة اختبار التسرّب (النصف الثاني من المخرَج ⑥)

- **التشغيل:** `php tests/tenant_leak_test.php` — رمز خروج 0/1 (صالح للأتمتة). المجلد محجوب عن الويب.
- **التغطية الحالية (27 اختبارًا):** عزل قراءة/كتابة/عدّ، تزوير هوية insert/update، whereRaw، حذف عابر، حذف ناعم واستثناء المحذوف، جداول غير مسجَّلة/مقيَّدة/معرّفات خبيثة، مراجع عامة قراءةً وكتابةً، سياق بلا شركة، أبناء عبر آباءٍ غير مملوكين، تجاوز غير مصرَّح، تسجيل التجاوز المصرَّح. Setup/Teardown ذاتيان (شركتا اختبارٍ مؤقتتان).
- **قاعدة الاعتماد (§4 بند ②):** كل شاشةٍ تُهاجَر تُضاف إلى `$MIGRATED_SCREENS` في ملف الاختبار، ولا تُعتمد إلا والحزمة كلها خضراء — «اختبارات التسرّب خضراء على كل شاشةٍ مُهاجَرة» هو معيار خروج المرحلة 1 حرفيًا.

## 6. حدود النسخة الأولى (مقصودة وموثقة)

- **لا JOIN مبنيًا بعد** — شاشات القوائم البسيطة (نطاق المرحلة 2) لا تحتاجه؛ يُضاف عند أول هجرةٍ تتطلبه **بتحديث هذا العقد واختباراتٍ له** (كل جدولٍ مستأجَرٍ في الـ JOIN يُعزل).
- سياق `forSystem` لواجهة `api/` المحمولة: الهوية من token خادمي — على مستدعيه ألا يمرر قيمة من العميل أبدًا (نفس عقد المصدر الموثوق).
- الجداول المقيَّدة العشرة تنتقل من `T_RESTRICTED` إلى فئتها الصحيحة كلٌّ مع هجرة وحدته (محرّك الموافقات مع ADR-08...).
