# محضرُ الاستعادةِ لنقطةِ زمن — ENG-01 · PR-06

> **◆ لمن يقرأ هذا:** هذا المحضرُ مكتوبٌ لمن **لم يبنِ النظام**. لا يفترض أنك
> تعرف أين تُخزَّن الملفات ولا كيف تعمل الخدمة. اتبع الخطواتِ بترتيبها.
> «فالمحضرُ الذي يفهمه بانيه وحدَه لا ينفع في الليلةِ التي يغيب فيها».

| البند | القيمة |
|---|---|
| الهدفُ المعلَن (RPO) | **15 دقيقة** — أقصى ما نقبل فقدَه من العمل |
| الهدفُ المعلَن (RTO) | **60 دقيقة** — أقصى ما نقبل انقطاعَه |
| آخرُ تجربةٍ ناجحة | `DR-2026-0001` — 2026-08-16 · RPO المقيس 0 د · RTO المقيس 2 ث |
| دوريةُ التجربة | **شهريًّا** — ونسخةٌ لم تُختبر ليست نسخة |
| المسؤول | دور 15 (إدارة الصلاحيات) بالاشتراك مع دور 19 (مدير المالية) |
| مكانُ تسجيلِ المحضر | شاشة `Governance/dr_restore.php` → جدول `dr_drills` |

## ① تفعيلُ سجلِّ الثنائيات (مرةً واحدةً — يحتاج صلاحيةَ مسؤول)

الإعدادُ **مكتوبٌ سلفًا** في:

```
C:\wamp64\bin\mariadb\mariadb11.4.9\my.ini      (المجموعة [wampmariadb64])
```

```ini
log_bin=mysql_bin
binlog_format=ROW
binlog_row_image=FULL
binlog_expire_logs_seconds=1209600   ; أربعةَ عشرَ يومًا
max_binlog_size=100M
sync_binlog=1
```

وما ينقص هو **إعادةُ تشغيل الخدمة بصلاحيةِ مسؤول**:

```bash
net stop wampmariadb64 && net start wampmariadb64
```

> شغّلْ موجّهَ الأوامرِ بـ«تشغيل كمسؤول» (Run as administrator)، أو من أيقونة
> WAMP: **MySQL → Service administration → Restart Service**.

ثم تأكّدْ:

```bash
php tools/eng01_checks_gate.php
```

`CK-16` يجب أن يصير أخضرَ بقيمة `ON`. ونسخةٌ احتياطيةٌ من `my.ini` محفوظةٌ
بجانبه باسم `my.ini.bak.eng01.<التاريخ>` إن احتجت الرجوع.

## ② النسخةُ الكاملةُ اليومية

```bash
"C:/wamp64/bin/mariadb/mariadb11.4.9/bin/mariadb-dump.exe" \
  -h127.0.0.1 -P3307 -u<المستخدم> -p<الكلمة> \
  --single-transaction --master-data=2 --routines --events \
  --databases equipation_manage > D:/backups/ems_full_$(date +%Y%m%d).sql
```

- `--single-transaction` يمنع قفلَ الجداولِ أثناء النسخ.
- `--master-data=2` **إلزاميّ**: يكتب داخلَ الملفِّ سطرَ `CHANGE MASTER TO`
  بموضعِ النسخةِ في السجل. ومن دونه لا تعرف من أينَ تُعيد التشغيل.
- **◆ احفظِ النسخةَ على قرصٍ آخرَ غيرِ قرصِ الخادم** — «ونسخةٌ على القرصِ
  نفسِه ليست نسخةً احتياطيةً بل نسخةً ثانيةً للخطرِ نفسِه».

## ③ الاستعادةُ إلى دقيقةٍ بعينِها

**افترضْ أن خطأً وقع الساعةَ 14:37 وتريد العودةَ إلى 14:30.**

### ٣-١ · أوقفِ الكتابةَ على القاعدةِ المصابة

أوقفْ خادمَ الويب (Apache) كي لا تُضاف كتاباتٌ جديدةٌ أثناء الاستعادة.

### ٣-٢ · استعدْ إلى **قاعدةٍ منفصلةٍ** أولًا — لا فوقَ المصابة

> **◆ لا تستعدْ فوقَ القاعدةِ الحية.** استعدْ إلى مثيلٍ أو قاعدةٍ منفصلة، ثم
> تحقّقْ، ثم بدّلْ. وهكذا جرت التجربةُ `DR-2026-0001`: على مثيلٍ مستقلٍّ على
> المنفذ 3399، والخدمةُ الحيةُ لم تُمسّ.

```bash
mysql -h127.0.0.1 -P3307 -u<المستخدم> -p -e "CREATE DATABASE ems_restore"
mysql -h127.0.0.1 -P3307 -u<المستخدم> -p ems_restore < D:/backups/ems_full_20260816.sql
```

### ٣-٣ · اقرأْ موضعَ النسخةِ من الملفِّ نفسِه

```bash
grep -m1 "CHANGE MASTER TO" D:/backups/ems_full_20260816.sql
```

سيظهر مثلُ: `MASTER_LOG_FILE='mysql_bin.000042', MASTER_LOG_POS=1547`

### ٣-٤ · أعِدْ تشغيلَ السجلِّ من ذلك الموضعِ حتى الدقيقةِ المطلوبة

```bash
"C:/wamp64/bin/mariadb/mariadb11.4.9/bin/mariadb-binlog.exe" \
  --disable-log-bin \
  --database=equipation_manage \
  --start-position=1547 \
  --stop-datetime="2026-08-16 14:30:00" \
  "C:/wamp64/bin/mariadb/mariadb11.4.9/data/mysql_bin.000042" \
  "C:/wamp64/bin/mariadb/mariadb11.4.9/data/mysql_bin.000043" \
  > D:/backups/replay.sql

mysql -h127.0.0.1 -P3307 -u<المستخدم> -p ems_restore < D:/backups/replay.sql
```

- الملفاتُ **بترتيبها** من ملفِّ النسخةِ فصاعدًا. اعرضْها بـ`SHOW BINARY LOGS`.
- `--start-position` تسري على **أولِ ملفٍّ فقط** — وهذا هو السلوكُ المطلوب.
- `--stop-datetime` هي **الدقيقةُ التي تعود إليها**. ولا ثانيةَ بعدَها.

### ٣-٥ · تحقّقْ قبلَ التبديل

```sql
SELECT COUNT(*) FROM ems_restore.ems_business_events;             -- يقارَن بما قبلَ الخطأ
SELECT MAX(created_at) FROM ems_restore.ems_business_events;      -- يجب ألا يتجاوز 14:30
```

**لا تُبدّلْ حتى يظهر أن ما بعدَ 14:30 لم يعد.**

### ٣-٦ · بدّلْ ثم شغّلْ

بعدَ التحقق: أعدْ تسميةَ القاعدةِ المصابةِ (لا تحذفْها) ثم فعّلْ المستعادة،
وشغّلْ Apache، وشغّلْ `php cron_jobs.php` مرةً للتأكد من عودةِ العامل.

## ④ سجّلِ المحضرَ فورًا — والتجربةُ لا تكتمل بلا محضر

من شاشة **`Governance/dr_restore.php`** املأْ:

| الحقل | ما تكتبه |
|---|---|
| البدء / الانتهاء | وقتُ بدءِ الاستعادةِ ووقتُ انتهائها |
| نقطةُ الاستعادة | الدقيقةُ التي عدتَ إليها (`--stop-datetime`) |
| هدفُ RPO | 15 |
| RPO المقيس | كم دقيقةً من العملِ فُقدت فعلًا |
| RTO المقيس | ثوانٍ بين ٣-١ و٣-٦ |
| صفوفٌ قبل / يجب ألا تعود / عادت فعلًا | من استعلاماتِ ٣-٥ |
| الحكم | `pass` فقط إذا كان «عادت فعلًا» = **صفرًا** |

> القاعدةُ ترفض حكمًا بـ`pass` وما بعدَ اللحظةِ عاد (`chk_drill_pass`) —
> فالحكمُ من القياسِ لا من الادعاء.
