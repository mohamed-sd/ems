# N-25 · توحيد التوقيت — تقرير الفحص الحاكم والقرار (الموجة ⑲)

> يُدرج في مخرجات التجربة ولو كانت النتيجة «إعدادٌ لا ترحيل» (ملحق UAT §12.6-⑤).

## NFR-01 · الفحص التمهيدي الحاكم — قِيس قبل أي تبديل (2026-08-02)

| القياس | القيمة |
|---|---|
| `NOW()` (القاعدة) | 2026-08-02 03:14:14 |
| `UTC_TIMESTAMP()` | 2026-08-02 00:14:14 |
| `@@time_zone` (جلسة وعام) | `SYSTEM` |
| `@@system_time_zone` | **Egypt Daylight Time** (UTC+3 صيفًا · +2 شتاءً) |
| PHP `date.timezone` (كان) | **UTC** |
| الفارق المقيس | **3 ساعات** (لا «ساعة» كما وُثّق سابقًا — القياس الحي يسبق) |

**الحكم:** التواريخ المخزنة عبر `NOW()`/`CURRENT_TIMESTAMP` (وهي عرف المستودع
المعلن: «المهل بساعة القاعدة») **محلية بتوقيت خادم النظام** — وكان التطبيق
على ساعة أخرى (UTC)، فالخطر الفعلي **ساعتان مختلطتان** لا مجرد اختيار منطقة.

## القرار — NFR-02 طُبِّق وNFR-03 أُعدّ بلا تشغيل

- **الإزاحة موسمية** (التوقيت الصيفي المصري): ترحيل NFR-03 «بإزاحة محسوبة»
  المسطّح **يفسد تواريخ الشتاء** — والترحيل الصحيح يتطلب تحويلًا واعيًا بالDST
  لكل عمود datetime في 342 جدولًا مع قلب كل الكتّاب لحظة واحدة.
- **المطبَّق (إعدادٌ لا ترحيل):** توحيد ساعة التطبيق على ساعة القاعدة —
  `date_default_timezone_set('Africa/Cairo')` في `config.php` (مطابقة
  `Egypt Daylight Time` بقواعد DST نفسها) خلف علم **`EMS_APP_TIMEZONE`**.
- **التحقق:** `php now == db NOW()` بفارق **0 ثانية** بعد التوحيد.
- **علم الرجوع المختبر:** `EMS_APP_TIMEZONE=UTC` في `.env` يعيد الحال السابقة
  في ثوانٍ بلا مساس بيانات.

## NFR-03 · خطة ترحيل UTC الكاملة — جاهزة ولا تُشغَّل (قرار مالك)

انظر [N-25_utc_migration_plan_ar.md](N-25_utc_migration_plan_ar.md): جرد أعمدة
datetime آليًّا · تحويل `CONVERT_TZ(col, 'Africa/Cairo', 'UTC')` بعد تحميل جداول
المناطق في MySQL · عدّاد صفوف قبل/بعد لكل جدول · قلب `time_zone='+00:00'`
للجلسات و`EMS_APP_TIMEZONE=UTC` معًا · والرجوع عكس التحويل بالدالة نفسها.
