# XF-01 — «البياناتُ الإضافية»: أمرٌ جاهزٌ للتعميم

> **الحالة (2026-08-19):** الشاشةُ الأولى **مُنفَّذةٌ ومُقاسة** (`Clients/clients.php`).
> والحزمةُ **جاهزةٌ ولم تُشغَّل** على غيرِها — بانتظارِ اعتمادِ المالكِ بعد التجربة.

## ① الفكرة في سطر

عمودٌ في وثيقةِ الأعمدةِ لا يعني حقلًا إلزاميًّا في نموذجِ الإضافة.
فالحدُّ الأدنى يبقى كما هو، وما زاد عليه يصير **بياناتٍ إضافيةً اختياريةً**:
مطويةً في الفورمِ خلفَ زرِّ «المزيد»، ومجموعةً واحدةً في الجدولِ تُظهَر وتُخفى.

**والمشكلةُ التي حلَّها ذلك، مقيسةً حيًّا:**

| المقياس | العدد | المصدر |
|---|---:|---|
| رؤوسُ أعمدةٍ محقونةٌ بلا وصلٍ بمصدر | **4,070** | `php tools/xf_plan.php --all` |
| موزّعةً على ملفاتِ شاشات | **293** | نفسُه |
| بتسمياتٍ فريدة | **1,229** | مسحُ `xf_scan_repo()` |

وكلُّ واحدٍ منها كان يُصيَّر «—» في كلِّ صفٍّ، ورأسُه موسومٌ **«بلا مصدر»** في منتقي الأعمدة.

كانت الشاشةُ تحمل **13 رأسًا محقونًا** + عمودَ حوكمةٍ واحدًا. والتصنيفُ بعدَ القياس:

## ③ القطعُ المركزيةُ — تُصلح لكلِّ شاشة

| الملف | الدور |
|---|---|
| `includes/extra_fields.php` | **السجلُّ المصدر**: منه يُرسم الفورمُ وتُجمع قيمُ POST وتُطبع خلايا الصفِّ وتُبنى نافذةُ التفاصيل. تصحيحٌ واحدٌ يسري على الكلِّ. |
| `includes/extra_fields_generated.php` | يكتبه `xf_apply.php` ويُدمج **تحت** المكتوبِ يدويًّا — فالمضبوطُ بيدٍ لا يدهسه آليّ. |
| `assets/js/ui-unification.js` | يعرف `data-fn-src`: لا يحشو الموصولَ ولا يسمه «بلا مصدر»، **و يحشوه من `data-xf` الصفّيِّ إن لم تطبعه الشاشةُ بعدُ** (شبكةُ أمانِ الترحيلِ الجزئيّ). |
| `assets/css/ems-forms.css` | قسمُ «المزيد» بإطارٍ **متقطّعٍ** يقول «اختياري» قبلَ القراءة + عرضُها في نافذةِ التفاصيل. |

### ◆ لماذا خطوةُ الرؤوسِ آمنةٌ وحدَها

ترحيلُ شاشةٍ خطوتان: **وسمُ الرؤوس** ثم **طبعُ الخلايا**. ولو وقعت الأولى وحدَها
لصار الصفُّ أقصرَ من ترويستِه، فتسقط كلُّ قيمةٍ تحت رأسٍ ليس لها.
لذلك يقيس `padGovernanceCells` الواقعَ من أوّلِ صفٍّ حقيقيّ: إن كان قصيرًا بمقدارِ
الأعمدةِ الموصولةِ **تمامًا** حشاها بنفسِه. ⇒ **الخطوةُ الأولى لا تكسر شيئًا، والثانيةُ تحسينٌ لا شرطُ سلامة.**

مُثبَتٌ بمسبارٍ في الحالاتِ الثلاث (موصولٌ بلا خلايا · موصولٌ بخلايا · محقونٌ بلا وصل): صفرُ انزياحٍ في الثلاث.

## ④ الأمرُ الجاهز — ثلاثُ خطواتٍ لكلِّ نطاق

### الخطوة ١ — خطِّط (قراءةٌ فقط · لا تكتب حرفًا)

```bash
php tools/xf_plan.php --screen=Suppliers/suppliers.php
```

```bash
php tools/xf_plan.php --dir=Suppliers/
```

```bash
php tools/xf_plan.php --all
```

يُنتج `docs/xf_plans/<slug>.json` (للأداة) و`.csv` (للأكسل — بعمودِ **«قرار المالك»** فارغًا).
وكلُّ عمودٍ يخرج بحكمٍ **وسببِه**، ولا يُسقَط عمودٌ من العدِّ بلا إعلان.

**التصنيفُ ثلاثيٌّ عمدًا:**

| الحكم | المعنى | العملُ اللازم |
|---|---|---|
| `BIND` | العمودُ **موجودٌ** في جدولِ الشاشة (أو مشتقٌّ منه) | وصلٌ — **بلا هجرة** |
| `NEW` | لا عمودَ له ولا اشتقاق | عمودٌ اختياريٌّ جديد (هجرة) |
| `BOUND` | يبثُّه `ems_gov_ctx()` سلفًا | **لا عمل** |
| `MANUAL` | ملتبسٌ — تسميةٌ خارجَ المعجم، أو جدولٌ لم يُستنبَط، أو **معنًى علائقيّ** | قرارُ مالكٍ |

> **لماذا `MANUAL` كبيرٌ ولن يصغر بالأتمتة:** 897 عمودًا منها **تسميةٌ علائقية**
> («مرجع التفويض» · «المرفق» · «مركز التكلفة» · «العملة») — إنشاءُ `VARCHAR` لها
> يخلق نسخةً نصيةً من علاقةٍ لها مفتاحٌ أجنبيّ، والنسختانِ تتفرّقان بلا إنذار.
> فتركُها قرارًا **أصحُّ من أتمتتِها**.

### الخطوة ٢ — عايِن (لا يزال بلا كتابة)

```bash
php tools/xf_apply.php --plan=docs/xf_plans/suppliers.json
```

### الخطوة ٣ — نفّذ

```bash
php tools/xf_apply.php --plan=docs/xf_plans/suppliers.json --apply
```

ثم — إن ولّد هجرةً:

```bash
php database/migrations/<الملفُّ المولَّد>.php
```

```bash
php database/migrate.php mark-applied <الملفُّ المولَّد>.php
```

```bash
php database/migrate.php dump-schema
```

وأخيرًا **البوابة**:

```bash
php tools/xf_gate.php
```

## ⑤ ما يفعله المنفِّذُ آليًّا وما يرفض

| الخطوة | آليّ؟ | المرساة |
|---|---|---|
| ① الهجرة (أعمدةُ `NEW`) | ✅ كامل | لا تلزم مرساة |
| ② صفُّ السجل | ✅ كامل | ملفٌّ مولَّدٌ منفصل |
| ③ وصلُ الرؤوس | ✅ كامل | التسميةُ الحرفيةُ داخلَ `<th data-fn|data-gov>` |
| ④-أ الاستدعاءُ وهويةُ الشاشة | ⚠️ بمرساة | `include '../config.php';` **وحيدًا** |
| ④-ب خلايا الصفّ | ⚠️ بمرساة | `echo "</tr>";` **وحيدًا** + متغيّرُ حلقةٍ معروف |
| ④-ج قسمُ «المزيد» | ⚠️ بمرساة | `<div class="pu-form-actions">` **وحيدًا** |
| ④-د جمعُ POST ودمجُه | ❌ يدويٌّ دائمًا | — |

**ولماذا ④-د يدويٌّ عمدًا:** الشاشاتُ تكتب بطرقٍ مختلفة (بوابةُ مستأجرٍ · خدمةٌ ·
محضَّرةٌ يدوية)، ودمجٌ أعمى في محضَّرةٍ **يُزيح `bind_param` فيمحو نصوصًا** — وهي
گوتشا مسجَّلةٌ في هذا المستودعِ وقعت فعلًا (14 نصًّا مُحيت). فالمنفِّذُ يُعلن الصنيعَ
المطلوبَ حرفيًّا ويتركه للمراجع:

```php
$xf_values = ems_xf_collect($XF_SCREEN, $_POST);
// ثم في الإدراج والتعديل:
$gate->insert('<table>', array_merge(array( /* حمولتك */ ), $xf_values));
```

**وضماناتُ السلامة:** نسخةٌ احتياطيةٌ `*.xfbak` قبلَ كلِّ ملفّ · `php -l` بعدَه ·
**وارتدادٌ فوريٌّ** عند أيِّ خطأِ صياغة. فلا يبقى ملفٌّ مكسورٌ في الشجرة.
ومرساةٌ غائبةٌ **أو متعدّدة** ⇒ تُتخطّى وتُعلَن بسببها، ولا يُخمَّن موضع.

## ⑦ التوسعةُ المستقبلية

- **تسميةٌ جديدةٌ في المعجم** ⇒ `xf_dictionary()` في `tools/xf_lib.php`.
  وأيُّ تسميةٍ تُضاف تُحوِّل صفوفَها من `MANUAL` إلى `BIND`/`NEW` في التخطيطِ التالي.
- **ضبطُ شاشةٍ بعينِها** (خياراتُ قائمةٍ · تسميةٌ أدقُّ · حقلٌ عريض) ⇒ اكتب صفَّها
  في `includes/extra_fields.php` يدويًّا — فالمكتوبُ يدويًّا **يغلب** المولَّد.
- **التراجع** ⇒ استرجع `*.xfbak`، واحذف صفَّ الشاشةِ من السجلِّ المولَّد.
  والأعمدةُ في القاعدةِ تبقى — وهي `NULL` فلا تضرُّ شيئًا.
