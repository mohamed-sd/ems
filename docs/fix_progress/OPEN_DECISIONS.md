# سجلُّ القراراتِ المفتوحة — ما ينتظر قرارَ المالكِ لا شفرةً

> يُقرأ آليًّا من `tools/fix_permgov_campaign.php`. وبندٌ هنا **مُعلَنٌ لا مُنفَّذ**:
> نصُّ قبولِه يقبل الإعلانَ بديلًا عن التنفيذِ صراحةً («أو يُعرض في تقرير الاكتمال
> بندٌ صريحٌ … بتاريخٍ ومالك»). فالإعلانُ وفاءٌ بالشرطِ لا التفافٌ عليه — والالتفافُ
> أن يُقال «مُنفَّذ» وهو ليس كذلك.

**تاريخُ آخرِ مراجعة**: 2026-08-14 · **مالكُ السجل**: مالكُ المنتج (m.sayed@equipation.sd)

## INJ-0328 — إدارةُ المشترياتِ المركزية (DEF-013 · DEC-H)

| | |
|---|---|
| **الحالة** | **مفتوح — ينتظر قرارَ المالك** |
| **القرارُ المطلوب** | أتُنشأ وحدةُ «المشترياتِ المركزية» بدورٍ وسايدبارٍ وشاشاتٍ مستقلّة، أم تبقى المشترياتُ التشغيليةُ هي القناةَ الوحيدة؟ |
| **لماذا ليس قرارَ مهندس** | إنشاءُ وحدةٍ تنظيميةٍ يغيّر هيكلَ الشركةِ وتبعياتِ الموظفين وسلاسلَ الاعتماد — وهو قرارُ مالكٍ لا خيارُ تنفيذ |
| **أثرُ التأجيل** | المشترياتُ تعمل اليومَ بقناةٍ واحدة؛ ولا عطلَ وظيفيّ. الأثرُ حوكميٌّ: لا فصلَ بين الطالبِ والمشتري على مستوى الوحدة |
| **ما يُغلقه** | قرارٌ موثَّقٌ برقمٍ وتاريخٍ وموقِّع، ثم إمّا إنشاءُ الوحدةِ أو إقفالُ DEC-H بـ«لا تُنشأ» |

## INJ-0558 — سقفُ الشراءِ التشغيليِّ ومرجعُ تجاوزِه

| | |
|---|---|
| **الحالة** | **مفتوح — ينتظر رقمًا من المالك** |
| **القرارُ المطلوب** | ما قيمةُ سقفِ الشراءِ التشغيليِّ الذي يُصعَّد فوقَه الطلبُ إلى نائبِ المالية؟ وبأيِّ عملة؟ |
| **لماذا ليس قرارَ مهندس** | رقمٌ ماليٌّ يحدّد أين تقع سلطةُ الصرف — سياسةٌ لا هندسة |
| **الآليةُ جاهزة** | `signing_authorities.amount_cap` و`AuthorityGuard::sign()` يُنفّذان أيَّ سقفٍ يُدخَل، والتصعيدُ يقع تلقائيًّا (مُثبَتٌ بشاهدِ `authority_cap_escalation_test`) |
| **ما يُغلقه** | إدخالُ السقفِ في `signing_authorities` لدورِ المشترياتِ وإشعالُ عَلَمِ `signing_caps` للكيان |

## INJ-0588 — المراجعُ الداخليُّ المستقل (وحدةٌ تنظيمية)

| | |
|---|---|
| **الحالة** | **مفتوح — ينتظر قرارَ المالك** |
| **القرارُ المطلوب** | أيُعيَّن مراجعٌ داخليٌّ مستقلٌّ بوحدةٍ وتبعيةٍ وحدود، أم تبقى المراجعةُ ضمنَ الحوكمةِ والالتزام؟ |
| **لماذا ليس قرارَ مهندس** | استقلالُ المراجعِ شرطُه التبعيةُ التنظيمية — تعيينٌ لا تهيئة |
| **أثرُ التأجيل** | التدقيقُ قائمٌ ويُكتب (`activity_logs` بـ74,163 صفًّا بقيمةِ «قبل»)، لكن **مَن يراجعه** ليس مستقلًّا تنظيميًّا |
| **ما يُغلقه** | قرارٌ برقمٍ وتاريخٍ وموقِّعٍ يُنشئ الوحدةَ ويحدّد تبعيتَها، ثم الدورُ ٣٣ وشاشاتُه |

## INJ-0484 — حواجزُ اعتمادِ الإصدار

| | |
|---|---|
| **الحالة** | **مفتوح — ينتظر تعريفَ المالكِ للحواجز** |
| **القرارُ المطلوب** | ما الحواجزُ التي تمنع اعتمادَ إصدارٍ للإنتاج؟ (البوابةُ الخضراء؟ نسبةٌ مرجَّحةٌ دنيا؟ صفرُ P0 مفتوح؟) |
| **لماذا ليس قرارَ مهندس** | معايير الإفراجِ قرارُ مالكِ منتجٍ لا خيارُ تنفيذ |
| **الآليةُ جاهزة** | البوابةُ تُرجع صفرًا عند النجاحِ وغيرَ صفرٍ عند سقوطِ أيِّ اختبار (`regression_exit_contract_test`)، وتقريرُ الحالةِ يُعطي الأرقامَ الثلاثةَ والنسبةَ المرجَّحة |
| **ما يُغلقه** | قائمةُ حواجزَ مكتوبةٌ، ثم فاحصٌ يمنع الاعتمادَ ما دام حاجزٌ مفتوحًا |

## القاعدةُ الحاكمةُ لهذا السجل

بندٌ يُدرَج هنا **لا يُعدُّ مُغلقًا** في العدِّ العام إلا إذا كان نصُّ قبولِه يقبل
الإعلانَ بديلًا — وأربعتُها تقبله. وما عداها يبقى مفتوحًا في السجلِّ الجامعِ
حتى يقع القرارُ ويُنفَّذ.
