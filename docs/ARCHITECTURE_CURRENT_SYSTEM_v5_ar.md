> **الحالة**: هذا الإصدار (v5) هو **المرجع الحالي**. يَخلُف v4 (2026-07-12) ويحفظه تاريخًا (v1/v2/v3/v4 محفوظة).
> **تاريخ التحرير**: 2026-07-14.
> **قاعدة التحرير**: «الكود هو الحقيقة» — كل رقمٍ هنا مقيسٌ من القاعدة/الشجرة الحيّة لحظةَ التحرير، لا منقولٌ عن وثيقة.

## 1. الملخّص التنفيذي المعماري
EMS منصّةُ إدارة معدّات/مقاولات (PHP إجرائي + MySQL) تُهاجَر تدريجيًّا — بلا كسر إنتاجي — من مونوليث متمركز حول الصفحة إلى معماريةٍ محوكمةٍ بأربع طبقات، عبر **«الخنق التدريجي» (Strangler)**: كل شاشةٍ تُنقل خلف **بوابة عزل الشركة `TenantDb`** واحدةً واحدة، بمقياسٍ صارم (`T3 = صفر نداء SQL خام`) وجولةٍ ذهبيةٍ مطابقةٍ بايتيًّا قبل/بعد (أو تحقّق عزلٍ مباشرٍ حين يكون الأصل مكسورًا).

**اللقطة المقيسة الآن** (2026-07-14):
| المقياس | القيمة | تغيّرٌ عن v4 |
|---|---|---|
| جداول القاعدة (BASE TABLE) | **148** | = |
| الترحيلات المطبَّقة (schema_migrations) | **50** | 47 → 50 (M4/M5/M6) |
| جداول تحمل `company_id` | **123 / 148** | = (M4/M5/M6 عبّأت NULL في أعمدةٍ قائمة، لم تُضِف أعمدة) |
| أعمدة دفتر الأحداث `fin_financial_events` | **41** | = |
| أحداث الدفتر الحيّة | **10** | = (**الناقل غير مَمْسوس**) |
| ملفات خلف البوابة (مقيس `ems_tenant_db(`) | **48+** | ~44 → 48+ |
| قدرات عقد البوابة (دوال عامة) | **13** | +3 قدرات |
| وحدات المرحلة 3 المكتملة | **5 من 6** (الصيانة·المعدات·العقود·الموظفون·المالية) | 1 → 5 |
| اختبارات المنصّة الأربع | **123 + 34 + 15 + 17 = 189 ناجحة، صفر فاشل** | صفر انحدار |

**أين نحن في الطريق**: المرحلة 0 (أساسات الأمان) والمرحلة 1 (البوابة + الفرص/المشتريات/النقل) **مغلقتان**. المرحلة 3 (هجرة الإدارات) **متقدّمة**: **المالية والصيانة والعقود مغلقةٌ كاملةً؛ والمعدات والموظفون مغلقان عدا ملفٍّ مؤجَّلٍ واحدٍ لكلٍّ** (`equipment_profile` و`employee_profile`) — كلاهما يقرأ جدول `timesheet` المقدّس فيُهاجَران معه أخيرًا. المتبقّي: مسحُ شاشاتٍ متفرّقة خارج الوحدات، ثم **الدوام (Timesheet) ختامًا** بعد عزل جواره المقدّس.

(بلا تغيير جوهريّ عن v4.)

## 3. المنظومة التقنية
PHP 8.4 · MySQL 8.4.7 (InnoDB، utf8mb4، **binlog=ROW**) · Apache (WAMP) · JS/jQuery + DataTables. الترحيلات تُدار حصريًّا عبر `database/migrate.php` (CLI، checksum، لقطة قبل كل `up`). **تنبيه تحقّقٍ مقيس**: opcache على الويب `revalidate_freq=2s` — عند تبديل نسخة ملفٍّ للمقارنة الذهبية يلزم انتظار ≥4 ثوانٍ قبل القياس وإلا خُدمت النسخة القديمة (قاعدةٌ منهجيةٌ اعتُمدت بعد ثلاث مقارناتٍ زائفة).

## 13. بوابة العزل `TenantDb` — العقد الموسَّع (ثماني قدرات)
**المبدأ**: لا شاشةٌ تلمس القاعدة مباشرةً؛ كلٌّ يعبر البوابة التي **تحقن عزل الشركة تلقائيًّا** وتفرض الحذف الناعم حيث يتوفّر، وتُغلق مغلقًا عند غياب سياق الشركة.

**سجل الجداول `TenantRegistry`** يصنّف كل جداول القاعدة (147 مُسجَّلًا) إلى: `T_TENANT` (مستأجَر بcompany_id) · `T_CHILD` (معزول بأبيه) · `T_GLOBAL` (كتالوج/منصّة) · **`T_CATALOG`** 🆕 (كتالوج مشترك: صفوفٌ عامّة NULL + صفوفٌ لكل شركة) · مع علامة **`managed`** 🆕 (كتالوجٌ عامٌّ يُكتب بحوكمة صلاحية الصفحة لا بالسوبر فقط).

**القدرات المحوكمة الآن (13 دالة عامة)** — كلٌّ وُلد من حاجة هجرةٍ فعلية بقرار موثَّق:
1. **CRUD الأساس**: `insert / update / softDelete / select / selectOne / count` — حقن company_id، حذف ناعم، وحارس **الحصانة §12** (`immutable_key`: صفٌّ يحمل بصمة حدثٍ منشور → يُرفض تعديله/حذفه حتى للسوبر).
2. **`runInTransaction`**: الأزواج الكتابية الذرّية — أيّ رفضٍ داخليّ = rollback الكل.
3. **`scopedQuery`**: المجاميع/الـJOINs — رمز `{TENANT_SCOPE}` تحقنه البوابة؛ الإثراء LEFT JOIN حصرًا؛ ممنوع ذكر company_id في SQL؛ وأعمدة `columns` **معرِّفاتٌ صرفة** (لا تعابير مثل `DISTINCT`/`AS` — تُميَّز/تُحسب في PHP).
4. **`replaceChildren`**: استبدالٌ كامل ذرّيّ لأسطر أبٍ (حذفُ القديم + إدراج الجديد بنطاقٍ مزدوج: الشركة + الأب المملوك المتحقَّق).
5. **`deleteChild`** 🆕 (القدرة السادسة): حذفُ صفِّ ابنٍ **صلبًا** بنطاقٍ مزدوج — لجداول السطور التزايُدية (`soft=false`) التي تُحرَّر صفًّا صفًّا لا استبدالًا كاملًا.
6. **`deleteRow`** 🆕 (القدرة الثامنة): حذفٌ صلبٌ لصفِّ كيانٍ مستأجَرٍ **بلا أبٍ إلزاميّ** (مثل `employees`: المورّد والمشروع اختياريان فلا يصلح النطاق المزدوج) — مقيَّدٌ بشركة السياق إلزامًا، strict، يُرفَض حيث يتوفّر حذفٌ ناعم ولغير `T_TENANT`.
7. **`forAllTenants`** (سوبر، رؤية عابرة محروسة مُسجَّلة).
8. **`forSystem`** (cron بلا جلسة — دورة شركاتٍ معزولة).

> القدرتان الجديدتان `T_CATALOG` (السابعة) وعلامة `managed` انبثقتا من هجرة الصيانة/المعدات (قوالب الفحص، أنواع المعدات، أكواد الأعطال)؛ و`deleteChild`/`deleteRow` من حذف سطور الخطة/الفحص/المشغّلين والموظفين. كلٌّ بتحقُّقٍ مستقل (deleteChild 4/4 · T_CATALOG 5/5 · managed 3/3 · deleteRow 4/4) وصفرِ انحدارٍ في حزمة التسرّب (123/123).

**التغطية الراهنة**: المرحلة 1 (20 ملفًا) + المالية (23) + الصيانة (9) + المعدات (17/18) + العقود (7) + الموظفون (13/14) — مقيس `ems_tenant_db(` في 48+ ملفًا.

## 14. الناقل الحي للأحداث (ADR-10) — الخط الأحمر صامد
**بلا أيّ تغيير عن v4**: `EventPublisher` (نقطة كتابةٍ واحدة، عطالةُ أثرٍ ببصمةٍ فريدة) → `fin_financial_events` (الدفتر) → `EventDispatcher` (توزيع exactly-once) → المستهلكون؛ والمُصالِح في `cron_events.php` يعيد نشر الفائت ويرصد اليتيمة.

**التحفّظ الملزم صامد**: مكوّنات الناقل الحيّة (`EventPublisher`, `EventDispatcher`, `includes/timesheet_event_hook.php`, `cron_events.php`) **لم تُلمس عبر كل هجرات المرحلة 3** (مقيس: عدّاد الدفتر ثابتٌ عند 10 طوال العمل؛ لا شاشةٍ من المهاجَرات تُصدر أحداثًا). بصمةُ خطّاف الساعات مقيسةٌ نصًّا: `{نوع}:{كيان}:{معرّف}:a{جيلُ الاعتماد}` (`timesheet_event_hook.php:83`، حيث الجيل = معرّف صفّ اعتماد المستوى الرابع) — فكلُّ اعتمادٍ نهائيٍّ جديدٍ حدثٌ مستقل، وإعادةُ إرسال النسخة نفسها تبقى معطَّلة (انظر §35 بند 1).

## 16. حارس صلاحية الفعل (ADR-06/K10) + CSRF المتدرّج
- **حارس الفعل**: `EMS_ACTION_GUARD=enforce`. يغطّي سطح AJAX (403 JSON منظَّم لغير المخوَّل).
- **CSRF المتدرّج (ADR-05)**: حقنٌ مركزيٌّ تلقائيٌّ + إنفاذٌ لكل مسار عبر `CSRF_ENFORCE_PATHS` في `.env`. **الوحدات المهاجَرة كاملةً في القائمة** (`/Finance/,/Procurement/,/Transport/,/Opportunities/`). القاعدة: كل وحدةٍ تُهاجَر تدخل القائمة يوم إغلاقها؛ **بند متابعة**: إضافة `/Maintenance/,/Contracts/,/Employees/` (والمعدات) للقائمة عند التثبّت النهائي، ثم قلبُ `EMS_CSRF_ENFORCE=true`.
