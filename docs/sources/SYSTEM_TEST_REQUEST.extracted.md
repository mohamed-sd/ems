# طلب تنفيذ تجربة تشغيلية شاملة لدورة إدارات منصة إنجاز

## أولًا: الهدف من التكليف

نريد إجراء تجربة تشغيلية شاملة ومتكاملة لمنصة إنجاز من أول نقطة في دورة العمل إلى آخر نقطة مالية ومحاسبية، على أن تُنفذ التجربة داخل النظام الفعلي كما لو أن القائم بها موظف حقيقي يستخدم المنصة يوميًا، وليس كمبرمج يقرأ الكود أو يختبر الشاشات بصورة منفصلة.

المطلوب من Claude Code ألا يكتفي بفحص الجداول أو مراجعة الملفات البرمجية، بل أن ينفذ دورة أعمال فعلية مترابطة، تبدأ من تسجيل العميل والفرصة البيعية، ثم العرض والعقد والمشروع، ثم الموردين والمعدات والمشغلين، ثم التشغيل والاعتماد والاستحقاقات والفوترة والتحصيل والتسويات والقيود المالية.

الهدف هو إثبات أن المنصة تعمل بوصفها نظام تشغيل مؤسسيًا واحدًا مترابطًا، وأن البيانات تنتقل بين الإدارات بصورة صحيحة دون انقطاع أو ازدواج أو إدخال يدوي متكرر أو تجاوز للصلاحيات.

# ثانيًا: منهجية التنفيذ الإلزامية

## 1. التعامل كمستخدم أعمال لا كمبرمج

يجب تنفيذ كل خطوة من خلال:

الشاشات الرسمية للنظام.

الصلاحيات والأدوار الحقيقية.

مسارات الموافقات المعتمدة.

الخدمات والواجهات الرسمية للنظام.

يُمنع إنشاء المعاملات مباشرة داخل قاعدة البيانات أو تجاوز الشاشات من أجل إظهار أن الدورة تعمل.

يجوز استخدام الاستعلامات المباشرة للقراءة والتحقق فقط بعد تنفيذ العملية، للتأكد من:

سلامة العلاقات.

انتقال البيانات.

عزل الشركات.

عدم التكرار.

صحة القيود.

اكتمال الأثر المالي.

## 2. بيئة الاختبار

يجب تنفيذ التجربة في بيئة UAT أو نسخة معزولة مطابقة للإنتاج، مع:

تثبيت رقم الـCommit الذي تبدأ منه التجربة.

أخذ نسخة احتياطية من قاعدة البيانات قبل البدء.

تسجيل وقت بداية الاختبار ونهايته.

منع التأثير على بيانات الإنتاج.

توفير خطة تنظيف أو تراجع لكل بيانات اختبارية.

إعادة قاعدة البيانات إلى حالتها الأصلية إذا تقرر إلغاء التجربة.

لا يجوز تنفيذ اختبارات تخريبية أو اعتماد مستندات مالية تجريبية داخل بيئة الإنتاج.

## 3. استخدام بيانات حقيقية مترابطة

نريد استخدام بيانات حقيقية مأخوذة من سجلات الشركة، مثل:

أسماء العملاء الحقيقيين.

المشاريع الحقيقية.

الموردين الحقيقيين.

أنواع المعدات وأرقامها.

المشغلين والموظفين.

نماذج العقود والأسعار الفعلية.

نظم التناوب والتشغيل المستخدمة.

العملات وآليات السداد الحقيقية.

لكن يجب استخدام هذه البيانات داخل بيئة الاختبار فقط.

لا نريد إنشاء أسماء وهمية منفصلة عن واقع الشركة مثل «عميل 1» و«مورد 1» و«حفار تجريبي». المطلوب أن تعكس التجربة العلاقات الحقيقية بين العملاء والمشروعات والموردين والمعدات والمشغلين.

إذا كان استخدام سجل حقيقي سيؤدي إلى التباس مع معاملة فعلية، يمكن إنشاء نسخة اختبارية مرتبطة به تحمل وسمًا واضحًا مثل:

UAT-2026

مع الاحتفاظ بالأسماء والعلاقات ونموذج العمل الحقيقي.

# الخامس عشر: الاختبارات السلبية الإلزامية

# الثامن عشر: المخرجات النهائية المطلوبة

# التاسع عشر: معيار النجاح النهائي

لا تعتبر الدورة ناجحة لمجرد أن الشاشات فتحت.

تُعتبر ناجحة فقط إذا أثبتت أن:

كل معلومة تُدخل مرة واحدة في موضعها الصحيح.

كل إدارة تستلم بياناتها من الإدارة السابقة.

لا يوجد إدخال يدوي مكرر للكمية أو السعر أو العميل أو العقد.

المشروع هو الأب التعاقدي.

الموقع أو المنجم نطاق تشغيلي.

المقاعد والحاويات والموردون والمعدات والمشغلون مرتبطون بصورة صحيحة.

الوحدات التشغيلية تنتقل إلى الاستحقاقات والفوترة.

الأحكام الثلاثة للعميل والمورد والمشغل مستقلة.

الفاتورة تنشأ من مستخلص معتمد.

التحصيل يظهر في كشف العميل والذمم.

القيد المالي متوازن.

إعادة الإرسال لا تكرر الأثر.

العزل يمنع انتقال البيانات بين الشركات.

كل موافقة لها هوية وصفة وتفويض.

كل خطأ أو استثناء ظاهر ومسجل.

جميع الأرقام يمكن الرجوع إلى مصدرها بنقرة أو مرجع مباشر.

## التعليمات الختامية إلى Claude Code

ابدأ أولًا بإعداد خطة تنفيذ الاختبار وبياناته وأدواره، ولا تبدأ إدخال المعاملات قبل اعتمادها.

بعد الاعتماد، نفذ دورة واحدة كاملة من البداية إلى النهاية، ثم توقف وقدم نتائجها قبل تعميم الاختبار على بقية الإدارات والمشروعات.

المطلوب ليس إظهار أن النظام يعمل، بل محاولة كسره وكشف كل موضع تنقطع فيه الدورة أو تتكرر فيه البيانات أو تتغير فيه الحقيقة بين الإدارات.
