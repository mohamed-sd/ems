# دليلُ الإقلاع — من صفرٍ إلى نظامٍ يعمل

> **الخلاصة في سطرين:** شغّلْ `php tools/doctor.php` أوّلًا وآخِرًا. وبعد كلِّ
> `git pull` شغّلْ `php database/migrate.php up` — الكودُ يصل بالسحب، وتسجيلُ
> الشاشات لا يصل إلا بالترحيل.

هذه الصفحةُ للإقلاع على جهازٍ جديد. تفاصيلُ المُثبِّت الكاملةُ في
[INSTALL_ar.md](INSTALL_ar.md)، وقواعدُ الترحيلات في
[MIGRATIONS_GUIDE_ar.md](MIGRATIONS_GUIDE_ar.md).

## ١. المتطلّبات

| المكوّن | المطلوب | ملاحظة |
|---|---|---|
| PHP | **8.2 فأحدث** | تفرضه `phpoffice/phpspreadsheet` في `composer.json` — على 8.1 يموت التطبيق عند `vendor/composer/platform_check.php` |
| خادمُ القاعدة | **MySQL 8.4** | ليس MariaDB — انظر التحذير أدناه |
| أباتشي | أيُّ إصدارٍ مع `mod_php` | حزمتُك المحلية (WAMP · XAMPP · Laragon) كما هي |
| امتدادات PHP | `mysqli` · `mbstring` · `json` · `zip` · `gd` · `openssl` | |

> ### ⚠️ MySQL لا MariaDB
> **XAMPP لا يحوي MySQL — يحوي MariaDB**، وهو منتجٌ مختلفٌ تفرّع عن MySQL لا
> إصدارٌ أقدمُ منه. مخطّطُ المشروع مبنيٌّ على MySQL 8: فيه ترتيبُ
> `utf8mb4_0900_ai_ci` الذي لا تعرفه MariaDB إطلاقًا، و34 عمودَ `JSON` أصيلًا
> يختلف سلوكُها بين المحرّكين. استيرادُ `database/schema/schema.sql` على MariaDB
> يتوقّف عند أوّل ترتيبٍ غيرِ معروف.
>
> **الحل:** ثبّتْ MySQL Community Server 8.4 واجعله صاحبَ المنفذ 3306.
> ولستَ مضطرًّا لترك حزمتك: أباتشي وPHP منها يبقيان كما هما — يُستبدل محرّكُ
> القاعدة وحدَه.
>
> **تنبيه المنفذ:** إن كان لديك محرّكان مثبَّتان فلن يعمل إلا مَن يحجز 3306
> أوّلًا، والآخرُ يفشل بصمتٍ في سجلّه بـ
> `[ERROR] Do you already have another mysqld server running on port: 3306?`
> ثمّ يظهر لك في المتصفح «خطأ في الاتصال بقاعدة البيانات» بلا سببٍ ظاهر.

**افحصْ جهازك قبل أيِّ خطوةٍ أخرى:**

```bash
php tools/doctor.php
```

الفاحصُ يعمل حتى قبل وجود `.env` أو القاعدة — يقول لك بالضبط ما ينقص.

## ٢. ملفُّ `.env`

```bash
cp .env.example .env
```

`.env` **لا يدخل المستودعَ أبدًا** (محجوبٌ في `.gitignore`) — فهو مختلفٌ على كلِّ
جهازٍ وفيه كلمةُ المرور. لذلك لا يصلك بـ`git pull`، وعليك إنشاؤه مرّةً واحدة.

**الإلزاميُّ ملؤه فقط:**

```
DB_HOST=localhost
DB_USER=ems_app
DB_PASS=<كلمة-المرور>
DB_NAME=equipation_manage
```

وكلُّ ما عداه له قيمةٌ افتراضيةٌ آمنة — اتركه كما هو ما لم تحتج غيرَه.

**مسارات الأدوات (`PHP_BIN` · `MYSQL_BIN_DIR`) اتركها فارغة:** تُكتشف وقتَ
التشغيل في `includes/portable_paths.php`. لا تكتب فيها مسارًا مطلقًا إلا إن قال
`doctor.php` إنه لزم.

## ٣. التنصيب (جهازٌ جديد فقط)

```bash
php database/install.php --check --config=install.json
```

`--check` لا يكتب شيئًا — يفحص فقط. ثمّ نفّذِ التنصيبَ الفعلي كما في
[INSTALL_ar.md](INSTALL_ar.md).

يبني المُثبِّتُ 315 جدولًا من `database/schema/schema.sql` و2337 صفًّا مرجعيًّا
من `seed_reference.sql`، ثمّ ينشئ من مدخلاتك: **شركة → موظّف → حسابُ دخول**.

## ٤. الترحيلات

```bash
php database/migrate.php status
```

```bash
php database/migrate.php up
```

### ⚠️ مصيدةُ الصلاحيات — اقرأها قبل أن تصطدم بها

مستخدمُ التطبيق `ems_app` صلاحياتُه `SELECT, INSERT, UPDATE, DELETE` فقط —
**بلا `CREATE`**، وذلك **تصميمٌ مقصود** (ADR-04: أقلُّ امتيازٍ للتطبيق). فلا
تُوسِّعْ صلاحياتِه؛ المسارُ الصحيح مستخدمُ ترحيلٍ منفصل:

```
DB_MIGRATOR_USER=ems_migrator
DB_MIGRATOR_PASS=<كلمة-مرور-قوية>
```

وأنشئه مرّةً على الخادم بمستخدمٍ إداري:

```sql
CREATE USER 'ems_migrator'@'localhost' IDENTIFIED BY '<كلمة-المرور>';
GRANT ALL PRIVILEGES ON `equipation_manage`.* TO 'ems_migrator'@'localhost';
FLUSH PRIVILEGES;
```

بدونه يفشل المُشغِّلُ بـ`CREATE command denied` — وهو ليس عطلًا بل إعدادٌ ناقص.

## ٥. بعد كلِّ `git pull` — الخطوةُ التي يُنساها الجميع

```bash
php database/migrate.php up
```

**لماذا هي إلزامية:** السايدبار لا يُكتب في الكود — يُبنى من جدول `nav_items`
باستعلامٍ حيٍّ مع كلِّ طلب (`includes/unified_nav.php`). فالشاشةُ الجديدة:

| ما يصلك بـ`git pull` | ما لا يصل إلا بالترحيل |
|---|---|
| ملفُّ الشاشة (`main/my_workspace.php` مثلًا) | صفُّها في `modules` |
| | إذنُها في `role_permissions` |
| | رابطُها في `nav_items` |

فإن سحبتَ ولم تُرحِّلْ رأيتَ بالضبط: **روابطَ ناقصةً في السايدبار، وهبوطًا على
الداشبورد القديمة** — والملفُّ الجديدُ موجودٌ عندك طوالَ الوقت. العَرَضُ بياناتٌ
لا كود. و`doctor.php` يكشف هذه الحالةَ بالتحديد في بند «سلامةُ التنقّل».

**ومَن يدخل من بوّابة الشركات (`/company/`) يخرج ويدخل بعد الترحيل** — الصلاحياتُ
تُخزَّن في الجلسة عند الدخول (`company/auth.php`)، فلا يرى الجديدَ حتى تتجدّد.
أمّا البوّابةُ الرئيسيةُ فتقرأ من القاعدة حيًّا ولا تحتاج ذلك.

## ٦. حين لا يعمل شيء

**ابدأ دائمًا من:**

```bash
php tools/doctor.php
```

| العَرَض | الأرجح |
|---|---|
| «خطأ في الاتصال بقاعدة البيانات» | القاعدةُ غيرُ منصَّبة، أو محرّكٌ آخرُ يحجز 3306 |
| `Failed opening required '…/session_bootstrap.php'` ‏و`in Unknown on line 0` | `.htaccess` قديمٌ فيه `auto_prepend_file` بمسارٍ مطلق — اسحبِ آخرَ الكود |
| `Composer detected issues… requires PHP >= 8.2` | إصدارُ PHP أقدمُ من المطلوب |
| `CREATE command denied` | `DB_MIGRATOR_USER` غيرُ مضبوط — الفقرة ٤ |
| السايدبارُ ناقصٌ / داشبوردٌ قديمة | ترحيلاتٌ لم تُشغَّل — الفقرة ٥ |
| `Unknown column …` في شاشة | ترحيلاتٌ لم تُشغَّل — الفقرة ٥ |

## ٧. قاعدةٌ للمساهمين

**لا تكتبْ مسارًا مطلقًا (`C:/…`) ولا اسمَ حزمةٍ (`xampp` · `wamp64`) في أيِّ ملفٍّ
يدخل المستودع.** حدث ذلك سابقًا في `.htaccess` فسقط المشروعُ على كلِّ جهازٍ لا
يملك ذلك المسارَ حرفيًّا. يحرس هذه القاعدةَ الآن:

```bash
php tests/portability_test.php
```

ويحرس معها أنّ كلَّ مفتاحٍ يقرأه الكود بـ`ems_env()` موثَّقٌ في `.env.example` —
مقارنةً آليّةً، فلا تتقادم.
