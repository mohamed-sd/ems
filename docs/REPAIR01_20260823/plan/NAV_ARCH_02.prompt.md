# ⛔⛔⛔ ٠ · قواعدُ لا تُخالَف

1. **القاعدةُ المركزيّة (§3)** — لا تُتجاوَز أبدًا:
   ```
   Permission grants access;  Placement grants navigation.
   ```
   **الصلاحيّةُ تجيب: أيستطيع فتحَها؟ · والموضعُ يجيب: أله مكانٌ معتمَدٌ هنا؟**
2. **⛔ لا تبدأْ بالحذف (§4)**. الترتيبُ الملزِم:
   `نفهم → نصنّف → نحكم → نبني النموذجَ الجديد → نصيّره بالظلّ → نختبر → ثمَّ نتقاعد`.
   ⛔ **ولا تُخفى شاشةٌ مستعمَلةٌ بلا تصنيفٍ وبديلِ وصولٍ ودليلٍ ومصير.**
3. **`No Placement = No Sidebar Render` (§22)** — **حتى لو `can_view = 1`**.
   ⛔ **والصلاحيّةُ تبقى صحيحةً**: «اختفى من السايدبار» ≠ «سُحبت صلاحيّتُه» (§42).
4. **لا توقّف (§35)**: `Block the affected Placement, not the program`.
   ⛔ «هل أكمل؟» · ⛔ «أنتظر توجيهك» · والبديلُ سطرُ تقدُّمٍ ثمَّ البندُ التالي.
5. **⛔ ولا تُعدَّل الأهدافُ من الواقع (§14·§17)** — `Governing Source → Target →
   Implementation` لا العكس. **والدليلُ لا يُضاف إليه `Legacy` لأنّ الناسَ
   يستعملونه** — إلّا بإثباتِ `TRUE_TARGET_GAP` بشروطِه السبعة.
6. **`G-CLAIM-01` نافذ**: الكسرُ المقيسُ لا نسبةٌ مخترَعة.
   **وكلُّ تغييرِ قاعدةٍ بهجرةٍ لها عكسٌ `_down.php`** · ⛔ ولا تعديلَ يدويّ.
7. **⚠ الشجرةُ محبوسةٌ الآن**: خطّافُ الالتزامِ يردُّ كلَّ شيءٍ بسببِ ارتدادِ
   شاهدِ `FR-GOV-006` (`tests/injfrd01_gov006_finding_intake.php`).
   ⭐ **أصلِحْه أوّلًا** — ⛔ ولا تتخطَّ خطّافًا بـ`--no-verify`.

## ③ التصنيفُ الآليُّ قبل البشر (§18) — ⭐ **أهمُّ طورٍ في الجولة**

**⛔ لا تُرسلْ مئاتِ البنودِ إلى المالك.** صنِّفْ آليًّا ما يُصنَّف:

| الحالة | الحكمُ الآليّ |
|---|---|
| له موضعٌ أصيلٌ في إدارةٍ أخرى وظهورُه هنا بالصلاحيّةِ فقط | `CROSS_WORKSPACE_PERMISSION_ONLY` ⇒ **لا يظهر** |
| تبويبٌ/سجلٌّ تابع | `MOVE_TO_PARENT` |

| أداةُ منصّة | `GLOBAL_SHELL` |
| شخصيّ | `MOVE_TO_WS_MY` |
| إرثٌ بلا هدفٍ وله استعمال | `LEGACY_REQUIRES_DOMAIN_REVIEW` |
| إرثٌ بلا استعمالٍ ولا تبعيّة | `RETIRE_CANDIDATE` |
| وظيفةُ أعمالٍ لا يقابلها هدف | `TARGET_GAP_CANDIDATE` |

**ثمَّ يُرفَع غيرُ المحسومِ وحدَه** — وبسلّمِ §34 الرباعيِّ:
قواعدُ المعماريّة ← مالكُ المجال ← الحوكمة ← **المالكُ أخيرًا** (‏لأربعِ حالاتٍ
فقط بنصِّ §34).

⛔ **والنموذجُ الثنائيُّ «يبقى/يُخفى» ملغًى (§19)** — الأحكامُ العشرةُ:
`KEEP_PRIMARY` · `KEEP_SECONDARY` · `MOVE_TO_WS_MY` · `MOVE_TO_GLOBAL_SHELL` ·
`MOVE_TO_PARENT` · `CONTEXTUALIZE` · `REPLACE` · `REDIRECT` · `RETIRE` ·
`TARGET_GAP_REVIEW` · `ESCALATE`.

⭐ **وملفّي `SIDEBAR_LAYER_MAP.xlsx` يعطيك مادّةَ التصنيفِ جاهزةً**: كلُّ
ظهورٍ بطبقتِه ومساحةِ مالكِه — **فالـ323 المستعارةُ لها مالكٌ معروفٌ سلفًا**
فتُصنَّف آليًّا بالأغلب.

## ④ العابرُ للإدارات (§12) — الحالاتُ الخمس

لكلِّ ظهورٍ عابرٍ **حدِّدْ نوعَ الاحتياجِ لا تنقلِ الشاشة**:

| الحالة | العلاج |
|---|---|
| أ — يحتاج المعلومةَ فقط | **إسقاطٌ للقراءة** في سياقِه — ⛔ لا تُنقَل الشاشة |
| ب — يحتاج طلبَ إجراء | **طلب/تحويل** (صيانة · شراء · ترحيل · صرف) |

**والقاعدةُ (§13)**: `Consumer reads; Owner writes` — ⛔ والتشغيلُ لا يأخذ
ملفّاتِ الموظفين في سايدباره لمجرّدِ أنّه يستطيع قراءتَها.
